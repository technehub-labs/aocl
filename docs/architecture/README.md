## Implementation status

- **CR-002's machine-readable tranche is implemented and validated** — `schema/canonical-loop.schema.json`, `src/aocl/metamodel.py` (MM-001..018 + migration + ADR-006 binding rule), `examples/canonical-loop.yaml` (acceptance criterion 12), `examples/loop-modeler-model.yaml` (migration source).
- **CR-006's machine-readable tranche is implemented and validated** — `schema/behavioral-spec.schema.json` (the BehavioralSpecification contract), `src/aocl/behavior_spec.py` + `aocl-behavior-spec` (BSS-001..036 native validation, four-level conformance §17 with simulation readiness reported separately per BSS-035/036, ADR-007 E/C/V_d anchor integrity, §20 migration), and `examples/behavioral-spec.yaml` (the eight reference patterns A–H, acceptance criterion 24). The pattern-H governed-learning boundary (BSS-030) and the BSS-023 authority rule (an Action's existence grants nothing without an AuthorizedBy reference) are enforced, not just representable.
- **CR-010's machine-readable tranche is implemented and validated** — the CR is baselined (`AOCL-CR-010.md`, Proposed, P27–P34, EXE-001..040, AD-010-01..12), with `schema/execution-semantics.schema.json`, `src/aocl/execution.py` + `aocl-execution` (native validation, the §17 profiles, and mode-specific **engine readiness** — logical vs state-based, distinct from structural conformance), and `examples/execution-definition.yaml` (the StateBased reference binding spec + scenario + models, AC-16/17). Nearly every policy is single-valued by design: graph-faithful activation with a declared entry, guards before effects, authority always checked, stale evidence blocks, deterministic tie-breaking, approvals suspend, unhandled exceptions escalate, safe states verified, seeded determinism, full trace coverage — and the load-bearing rule: **`controllerVisiblePolicy: PerScenarioDeclaration` with Runtime enforcement is the only conforming choice** (`Full` is structurally forbidden) — the simulated Controller never receives the scenario's hidden ground truth, which is what makes the data-veracity experiments valid. The §19 migration carries the sim canvas's implicit policies (human response, escalation windows, HOOTL novelty-only) into a Draft ExecutionDefinition as *carried* semantics, never promoted. The engines (CR-011/012) now have a normative contract to implement against.
- **CR-009's machine-readable tranche is implemented and validated** — `schema/scenario.schema.json` (the ScenarioLibrary contract), `src/aocl/scenario.py` + `aocl-scenario` (SCN-001..057 native validation, the ten conformance profiles of §21 plus mode-specific readiness per AD-009-15), and `examples/scenario-library.yaml` (the §23 congestion-and-recovery scenario with variants C and F, acceptance criteria 27–28). Enforced, not just representable: actual/observed/estimated initial states stay distinct (SCN-011, AD-009-04 — a scenario may hold the plant at 72 ms while the controller sees 48 ms); no silent defaults — non-Explicit initialization needs a declared source (SCN-013); **every disturbance declares what the Controller may know about it** (SCN-027, §11.5 — no hidden ground truth leaks to the simulated controller); event dependencies are cycle-checked (SCN-034); parameters are range-checked (SCN-015); stochastic scenarios declare their randomization basis (SCN-049) and external datasets need stable snapshots (SCN-050); an Incompatible scenario can never be silently Approved (SCN-053). The §24 migration surfaces the sim canvas's engine-embedded scenario data (model/behavior.yaml's four scenarios, disturbances and invariants) as Draft skeletons with the hard-coding inventoried.
- **CR-008's machine-readable tranche is implemented and validated** — `schema/evidence-model.schema.json` (the EvidenceModel contract), `src/aocl/evidence_model.py` + `aocl-evidence` (VER-001..050 native validation, the nine conformance profiles of §19 reported separately), and `examples/evidence-model.yaml` (the §21 network-assurance chain, acceptance criteria 22–23). Enforced, not just representable: execution evidence never establishes an outcome (VER-036) and transition claims need established-state evidence, not the command (VER-034); Failed / Inconclusive / Conflicting stay distinct with conflict records preserved unresolved (VER-024, AD-008-08/10); self-verification is honestly labeled and safety-critical claims require independent assurance (VER-029/030); simulation evidence carries run/scenario/seed/engine identity and never substitutes for operational evidence (VER-039..042, AD-008-11); positive results require evidence, dispositions never overwrite results, and incomplete chains are reported (VER-014/017/050, AD-008-13). The §22 migration carries control-model verification references into Draft skeletons and deliberately does NOT convert assessment or realization scores into evidence records.
- **CR-007's machine-readable tranche is implemented and validated** — `schema/control-contract.schema.json` (the control-model contract), `src/aocl/control_contract.py` + `aocl-control-contract` (CTM-001..040 native validation, the seven conformance profiles of §19 reported separately with simulation readiness assessed independently per AD-007-12), and `examples/control-contract.yaml` (the §17 network-assurance reference, acceptance criterion 21). Enforced, not just representable: the six-way state distinction (CTM-008), estimates name their estimator (CTM-012), authority never inferred — every authority reference must resolve to a declared AuthorityDefinition (CTM-028) and overlapping scopes require explicit coordination (CTM-029), execution ≠ outcome via evidential-strength matching of postcondition claims against their supporting signals (AD-007-09), safety/regulatory invariants binding on touching contracts (CTM-033), and units never silently mixed (CTM-006). The §21 migration carries goal reference conditions into Draft skeletons while deliberately NOT converting controlled-system bindings into authority.
- **Simulation evidence** ([ADR-006](../decisions/adr-006-simulation-evidence-and-architecture-alignment.md)): 7/7 plausibility invariants hold; findings F1–F4 are disposed against this CR sequence (F1 aggregation-binding → CR-002/CR-003 implementation; F2 burden-shift → CR-003; F3 sandbox containment → CR-004/CR-007; F4 velocity fit → CR-002 (done: binding fields) + CR-007).
- **Hybrid simulation** is realized: logical mode (`site/simulation.html`) + state-based mode (`tools/sim_check.py`, `site/sim.js`), parity pinned in `tests/sim-parity.json`.

**Modeling stage complete (machine-readable):** CR-002 (canonical metamodel) + CR-006 (what the loop is specified to do) + CR-007 (what control actions and state transitions mean) + CR-008 (how behavior and outcomes are verified) + CR-009 (under what conditions behavior is evaluated) — each with schema, native validator, reference instance and migration. The `scenarioBindings` hooks in the behavioral spec and control model (BSS-036, AD-007-12) now have a target format; the readiness gates can light up as soon as those bindings are made.

**Cost-benefit thesis as programme policy** ([ADR-007](../decisions/adr-007-realization-cost-benefit-instrument.md)): realization is the core decision instrument; E/C/V_d measurement anchors bind into CR-006; the L3 investment gate governs L4–L5 tooling and investment (exception-driven, evidence-driven).

Next per the review's sequence: **AOCL-CR-011/012 (the simulation engines)** implement the CR-010 contract — the execution semantics, their readiness gates, and the visibility enforcement they must honor are now normative. CR-013 (trace and replay) owns the trace format; CR-010 declares the obligatory record classes.
